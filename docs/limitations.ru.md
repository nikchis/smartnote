# Ограничения

Поведение, которое может удивить пользователя, хранящего заметки на сервере или работающего на
нескольких устройствах. Для пользователей; пределы защиты описаны в разделе
[Безопасность](security.ru.md#что-не-защищено), пределы поиска по смыслу — в разделе
[Поиск](search.ru.md#семантический-поиск).

- Backup и Restore заменяют весь набор заметок на другой стороне, как в v1. Перед удалением чего-либо
  они спрашивают подтверждение и называют число удаляемых заметок.
- Фразу синхронизации нельзя изменить, пока на сервере есть заметки.
- Выход из системы или выключение компьютера закрывают Smartnote без вопроса о закрытии, как
  SIGTERM: несохранённые копии на сервер не делаются, локальные заметки сохраняются. Сохраняйте
  данные на сервер перед выходом из системы.
- Яндекс Диск: два Backup, сделанные почти в один момент с двух устройств, могут потерять один из
  них. Оба получают одну ревизию, поэтому предупреждение о более старом хранилище этого не
  замечает. Не работайте с двух устройств одновременно.
- Данные принадлежат приложению, чей client ID использован при входе. Со своим client ID или в
  сборке с другим встроенным хранилище будет другим и пустым; заметки под прежним остаются там.
- Яндекс Диск: вход действует около года, затем Smartnote просит войти заново («Sign in to Yandex
  Disk again.»). Имя аккаунта не показывается, только «Signed in».
- Яндекс Диск: Smartnote не видит корзину Диска и не может её очистить. Если прежние копии
  контейнера попадут туда, они займут место; их можно удалить вручную в веб-интерфейсе Диска.
- Яндекс Диск: большой набор заметок при медленном соединении может сохраняться минутами. Операция
  ограничена 10 минутами (60 секундами для сервера SSH + PostgreSQL).
- Контейнер занимает не больше 64 МиБ. Больший набор отклоняется сообщением «Notes do not fit into
  the remote storage (64 MiB).»
- Фразу синхронизации нельзя изменить, пока в хранилище на Яндекс Диске есть заметки, как и на
  сервере.
- После «The result of the backup is unknown. Connect again to check the remote storage.» нажмите
  **OK** в Settings (или перезапустите Smartnote), чтобы подключиться снова: Smartnote сначала доводит до конца незавершённую запись и, пока
  это не удалось, не трогает хранилище.
- Предупреждение о том, что удалённое хранилище старее последней синхронизации этого устройства,
  действует и для сервера, и для Яндекс Диска; см.
  [Яндекс Диск](yandex-disk.ru.md#когда-хранилище-старее-устройства).
- Возврат с 2.2.0 на 2.1.0 оставляет `local.db` читаемым. Но 2.1.0 считает сохранённые настройки
  Яндекс Диска неполными настройками PostgreSQL, и Connect завершается ошибкой валидации
  «invalid ssh_host: is required» (не сетевой ошибкой SSH). Очистите поля в Settings версии 2.1.0; локальные заметки не затрагиваются.
- После возврата на 2.1.0 и обратно на 2.2.0 ревизии, которые Smartnote помнит для хранилищ, с
  которых 2.1.0 переключался, могут устареть. Обычно это значит лишь, что такое хранилище
  сравнивается как новое. В редком случае (2.1.0 восстановил данные из откаченного хранилища, а
  потом переключился на другое) Smartnote может предупредить, что хранилище старее, когда это не
  так, или не заметить Save другого устройства в нём, и тогда **Save** перезапишет эти данные без
  вопроса.
- Тип хранилища **None (local only)** сохраняет заполненные поля SSH + PostgreSQL, чтобы к ним можно
  было вернуться без повторного ввода. После возврата на 2.1.0 эти поля снова означают настроенный
  сервер, и 2.1.0 подключается с ними к PostgreSQL. Как обычно, она сравнивает заметки и спрашивает,
  прежде чем что-то заменить. Если это не нужно, очистите поля в Settings версии 2.1.0.
