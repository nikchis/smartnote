# Настройка сервера

Как подготовить собственный сервер, чтобы Smartnote сохранял на него заметки и восстанавливал их
оттуда. Для пользователей, которым нужны общие заметки на нескольких устройствах или копия вне
компьютера.

Синхронизация необязательна: с пустыми настройками Smartnote работает только локально. На сервере
нужны OpenSSH и PostgreSQL; Smartnote подключается по SSH и обращается к PostgreSQL через
SSH-соединение, поэтому базе данных не нужно слушать публичный адрес.

## Шаги

1. PostgreSQL слушает только loopback (`postgresql.conf`):

   ```
   listen_addresses = 'localhost'
   ```

   а `pg_hba.conf` пускает пользователя с loopback по паролю, например
   `host smartnote smartnote 127.0.0.1/32 scram-sha-256` (и `host smartnote smartnote ::1/128
   scram-sha-256` для хоста базы `localhost` или `::1`).

2. Создайте пользователя и базу данных, а схему либо создайте для пользователя сами, либо
   позвольте её создать приложению:

   ```sql
   CREATE ROLE smartnote LOGIN PASSWORD '...';
   CREATE DATABASE smartnote OWNER smartnote;
   -- либо: схема, которой владеет пользователь приложения
   \c smartnote
   CREATE SCHEMA smartnote AUTHORIZATION smartnote;
   -- либо: право создать её, чтобы это сделало первое подключение
   GRANT CREATE ON DATABASE smartnote TO smartnote;
   ```

   Пользователю, который не владеет уже существующей схемой, нужно
   `GRANT USAGE, CREATE ON SCHEMA smartnote TO smartnote`.

3. Доступ по SSH: в **Settings → Keys** создайте ключ (Ed25519) или импортируйте свой, нажмите
   **Export public** и добавьте строку в `~/.ssh/authorized_keys` SSH-пользователя на сервере.
   Пароль тоже подходит; если есть ключ, пароль пробуется после ключа.

4. В **Settings** укажите SSH-сервер, базу данных (хост `127.0.0.1`, `localhost` или `::1` с точки
   зрения SSH-сервера, порт, имя, пользователь, пароль) и фразу синхронизации; пустые порты
   означают 22 для SSH и 5432 для PostgreSQL, пустой хост базы — `127.0.0.1`. Нажмите
   **Test connection**, затем **OK**. При первом подключении Smartnote спрашивает, доверять ли
   ключу хоста сервера, и показывает его отпечаток SHA256; сравните его с ключами хоста на сервере,
   `for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done` (с настройками OpenSSH по
   умолчанию обычно предлагается ключ ECDSA).

## Фраза синхронизации

Все устройства с общими заметками используют одну фразу синхронизации (не короче 16 символов);
локальные пароли могут различаться. Фраза не покидает устройство: заметки шифруются ключом,
выведенным из неё, до того как попадают на сервер.

Что сервер может и чего не может узнать, описано в разделе
[Безопасность](security.ru.md#модель-угроз); как Backup и Restore обращаются с заметками на другой
стороне — в разделе [Ограничения](limitations.ru.md).
